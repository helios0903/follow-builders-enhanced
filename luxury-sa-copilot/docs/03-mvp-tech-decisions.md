# 阶段 2.1 · 调研与技术决策（管理者要问的问题）

> 方法论：AI 架构师不猜技术，而是先问对的问题、把调研委派出去、要利弊、再拍板。以下是本 MVP 做的关键决策。

---

### 决策 1｜形态：原生企业微信集成 vs Web App 模拟器
**问题**：我要验证的核心假设是"AI 排序 + AI 话术是否神奇有价值"。什么形态能用最快路径验证、剔除附带复杂度？
- 原生企业微信：贴近终局，但要企业资质、API 审批、合规——全是附带复杂度，且验证前根本拿不到。
- Web App 模拟器：一个下午能搭好整套后端逻辑（数据 → 排序 → 话术 → 交付），高保真模拟核心体验。

**决策**：**Web App 模拟器**。刻意"降级"以加速验证，先给概念去风险。

---

### 决策 2｜数据：真实 CRM 打通 vs 高保真模拟数据
**问题**：验证排序与话术逻辑，需要真实数据吗？
- 真实 CRM：打通成本高、涉隐私、拿不到。
- 模拟数据：只要**结构逼真**（覆盖沉睡/高潜/低频/高置信/低置信等分布），就足以验证排序算法和话术生成是否合理。

**决策**：**内置一份高保真模拟客户簿**（~14 位客户，覆盖关键分布）。数据结构按未来真实字段设计，便于日后替换为 CRM 接入。

---

### 决策 3｜排序算法：黑箱模型 vs 可解释的三维打分
**问题**：SA 不敢用看不懂的 tag（见 case §5）。排序要可解释吗？
**决策**：用团队自创的 **Potential × Relevance × Confidence** 三维加权打分，**每维可见、并生成一句 why-now**。可解释性本身就是对"tag 鸡肋"痛点的正面回应。

- **Potential**：历史消费额 + 购买频次 + VIP 层级 →"值不值得花时间"。
- **Relevance**：当前主推新品/campaign 与客户品类偏好的匹配度 →"现在联系有没有由头"。
- **Confidence**：结构化数据的充分程度 →"我们对这个判断有多少把握"（低置信 = H1 相似客群推断场景）。

---

### 决策 4｜话术生成：纯 LLM vs 模板引擎 vs 两者兼容
**问题**：MVP 要能随时演示（无网络/无 key 也要有"魔法"），又要能体现真实 LLM 的上限。
**决策**：**双通道**。
- **默认：内置话术引擎**——从客户结构化数据编织出本地化、非官方、含具体破冰点的开场白（始终可用，零依赖，适合当场演示）。
- **可选：接 Claude API**（填自己的 key）——用一段嵌入了"AI 管事实/SA 管情感、本地化、要回复"设计原则的 prompt 做真实生成，展示上限。
- 两种模式都**显式区分事实钩子 / 情感表达**。

> 注：在 Artifact 沙盒里浏览器对外 fetch 受 CSP 限制，"接 Claude API"通道在本地打开 `index.html` 时最稳；Artifact 预览用内置引擎即可完整体验。
